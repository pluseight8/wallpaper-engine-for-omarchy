# omawe — Wallpaper Engine для Omarchy

*Steam Wallpaper Engine wallpapers on Omarchy: library browser, per-monitor and per-workspace wallpapers, property editor,
playlists, auto-pause behind fullscreen windows and on battery, and an Omarchy theme generated from the wallpaper.
Needs `linux-wallpaperengine` and a Steam copy of Wallpaper Engine. Install: clone and run `./install.sh`; remove: `./uninstall.sh`.
The rest of this document is in Russian.*

Живые обои из Steam Wallpaper Engine на рабочем столе Omarchy (Hyprland + Quickshell).
Рендерит [linux-wallpaperengine](https://github.com/Almamu/linux-wallpaperengine); omawe управляет им:
библиотека, применение по мониторам, пауза, экономия батареи.

Нужна легальная копия Wallpaper Engine в Steam. omawe ничего из неё не копирует и не распространяет:
он только читает `project.json` и передаёт пути рендереру.

> Состояние: все четыре этапа сделаны. Чего нет и почему — в разделе «Ограничения».

## Требования

- Omarchy 4.5+ (оболочка на Quickshell)
- `linux-wallpaperengine` — `omarchy pkg aur add linux-wallpaperengine-git`
- Steam с установленным Wallpaper Engine (appid 431960) и подписками Workshop
- Rust (cargo) для сборки

## Установка

```bash
git clone https://github.com/pluseight8/wallpaper-engine-for-omarchy && cd wallpaper-engine-for-omarchy && ./install.sh
```

Пакетом: в репозитории есть `PKGBUILD` (`makepkg -si`), после установки один раз выполните `omawe-integrate`.

`install.sh` можно запускать повторно. Он:

- собирает и кладёт в `~/.local/bin`: `omawed`, `omawe`, `omawe-tui`, `omawe-pick`, `omawe-doctor`, `omawe-integrate`;
- ставит user-юнит `omawed.service` и включает его;
- копирует плагин оболочки в `~/.config/omarchy/plugins/org.pluseight.omawe` и включает виджет в баре;
- добавляет меню > Style > Wallpaper Engine, бинды (`~/.config/hypr/omawe.lua`), хуки `theme-set` и `post-update`;
- если стоит плагин `io.github.dkgamer02ai.wallpaper-engine`, **спрашивает и после согласия удаляет его** (`--yes` — без вопроса): тот убивает любые процессы рендерера, включая наши.

Файлы Omarchy в `/usr/share/omarchy` не меняются. Удаление: `./uninstall.sh` — возвращает фон темы.

## Использование

| Действие | Как |
|---|---|
| Панель: библиотека, фильтры, свойства, звук | ЛКМ по значку в баре |
| Быстрый выбор на весь экран | `Super+Alt+W`, меню > Style > Wallpaper Engine |
| Браузер в терминале (TUI) | `Super+Alt+Shift+W`, `omawe tui`, меню > Style > Wallpaper Engine |
| Следующие / предыдущие | `Super+Alt+]` / `Super+Alt+[`, колесо на значке |
| Пауза | `Super+Alt+\`, ПКМ по значку |
| Случайные | СКМ по значку, `omawe random` |

```
omawe apply <id|название> [--monitor DP-1] [--scaling fill|fit|stretch|default] [--clamp clamp|border|repeat]
omawe next | prev | random [--type video] [--tag Nature] [--fav]
omawe pause | resume | toggle
omawe stop                 # убрать живые обои, оставить статичный кадр
omawe list [--type T] [--tag T] [--rating R] [--search S] [--fav] [--sort recent] [--json]
omawe fav <id|название>    # избранное
omawe pick [фильтры list]  # пикер с превью
omawe props <id|название> [--monitor M]          # свойства и их значения
omawe prop <id|название> <ключ> [значение]       # изменить; без значения — по умолчанию
omawe preset save|load|rm <id|название> <имя>    # пресеты свойств
omawe preset reset <id|название>                 # сбросить все свойства
omawe volume <0-100> | mute
omawe set <настройка> <значение> | unset <настройка>
omawe apply <id|название> --workspace N          # свои обои для воркспейса
omawe test [id|название] [--all]                 # проверка совместимости
omawe workshop sync                              # подписчики и обновления из Steam
omawe open [id|название]                         # страница обоев или Workshop в Steam
omawe doctor [--fix]                             # диагностика
omawe status | watch | rescan | config
```

Без `--monitor` обои и свойства задаются для всех мониторов, с ним — только для указанного.

### TUI

`omawe tui` — браузер библиотеки в терминале в цветах текущей темы: список с поиском (`/`), фильтр по типу (`t`) и избранному (`F`),
превью выбранных обоев, выбор монитора (`m`), редактор свойств (`p`), пауза (пробел), звук (`s`), страница в Workshop (`o`).
Превью рисуется полублоками через ImageMagick, поэтому работает в любом терминале. Протокол kitty graphics не используется.

### Свойства обоев

Слайдеры, цвета, переключатели, списки и текстовые поля из `project.json` редактируются в панели (кнопка «Свойства»)
или командой `omawe prop`. Значения хранятся отдельно для каждых обоев и монитора. Цвет задаётся как `#rrggbb` в панели
и как три числа от 0 до 1 в CLI: `omawe prop "Neon Cube" customcolor "1 0 0"`.
У рендерера нет управления на лету, поэтому изменение перезапускает обои на этом мониторе (около секунды, без чёрного кадра).
Свойства типов file, directory и scenetexture не редактируются. Условия видимости свойств (`condition`) не учитываются: показываются все.

### Тема Omarchy из обоев

```bash
omawe set theme_sync true
```

После этого при каждой смене обоев из их кадра извлекается палитра, по ней собирается тема `omawe-live`
(`~/.config/omarchy/themes/omawe-live/`) и применяется штатным `omarchy theme set`. Поверхности берут преобладающий оттенок,
акцент — самый насыщенный цвет; цвета терминала сохраняют смысл (красный остаётся красным) и лишь сдвигаются к акценту.
Тема строится по обоям первого монитора. `omawe set theme_sync false` возвращает тему, которая была до включения.

### Обои по воркспейсам

`omawe apply <обои> --workspace 3` — эти обои показываются на мониторе, пока на нём открыт воркспейс 3;
`omawe stop --workspace 3` убирает привязку. Воркспейс важнее монитора, монитор важнее «всех мониторов».
Смена идёт той же бесшовной подменой, то есть около секунды на каждое переключение воркспейса.

### Проверка совместимости

`omawe test` по очереди запускает каждые ещё не проверенные обои на фоновом слое — под текущими обоями, на экране этого не видно —
и записывает результат: `ok`, `crash` (рендерер упал), `black` (чёрный кадр), `noframe` (кадра нет за 8 с).
Результат виден в `omawe list` и значком в панели; `crash` и `black` пропускаются при `next` и в плейлистах.
Удачный кадр заодно сохраняется как двойник. На всю библиотеку уходит около секунды на обои.

### Workshop

- `omawe workshop sync` запрашивает у публичного API Steam (`GetPublishedFileDetails`, без ключа и логина) число подписчиков,
  добавлений в избранное и дату обновления. Запрос идёт только по этой команде. После него работают `omawe list --sort popular`
  и отметка «в Workshop есть версия новее».
- `omawe open <обои>` или средняя кнопка мыши в панели открывает страницу обоев в Steam, `omawe open` — сам Workshop.
- Подписка и отписка делаются кнопкой в Steam: без ключа API подписаться извне нельзя. Имя автора и оценка в звёздах
  этим API не отдаются, поэтому их нет.

### Плейлисты

```toml
[playlist]
every = 30        # минут; 0 — выключено
on_login = true   # сменить обои при входе в сессию
random = false    # иначе по порядку
match_theme = false  # только обои, цвет которых близок к акценту текущей темы; при смене темы обои меняются сами
[playlist.filter] # какие обои участвуют: те же ключи, что у omawe list
fav = "true"
type = "scene"
[playlist.hours]  # по времени суток; при заданных часах таймер every не используется
"07:00" = "Purple Nebula"
"20:00" = "2235103792"
```

Плейлист не листает обои, пока они на паузе или остановлены.

## Настройки

`~/.config/omawe/config.toml`, применяется сразу после сохранения. То же самое меняет `omawe set <ключ> <значение>`
(значение хранится поверх файла, `omawe unset` его убирает). Все ключи необязательны, ниже значения по умолчанию:

```toml
fps_ac = 60
fps_battery = 30
battery = "fps"          # на батарее: "fps" — снизить FPS, "pause" — пауза, "static" — остановить рендерер
low_battery_percent = 20 # при таком заряде и ниже вместо battery действует low_battery
low_battery = "static"
pause_fullscreen = true  # пауза, когда все мониторы закрыты полноэкранными окнами
pause_maximized = true   # считать развёрнутое окно полноэкранным
stop_on_game = true      # остановить рендерер, пока открыта игра Steam (освобождает VRAM)
silent = true
volume = 15
automute = true
audio_processing = true
scaling = "fill"
clamp = "clamp"
sync_omarchy_bg = true   # держать штатным фоном Omarchy кадр текущих обоев
notify = true
theme_sync = false       # тема Omarchy из палитры обоев
```

## Как это устроено

- `omawed` — демон на Rust (tokio, один поток). Просыпается только по событиям: запрос CLI, событие Hyprland (`socket2`),
  смена питания (UPower по D-Bus), изменение папки Workshop или конфига (inotify), завершение рендерера.
- `omawe` — тонкий клиент, JSON по сокету `$XDG_RUNTIME_DIR/omawe.sock`.
- Индекс библиотеки — SQLite в `~/.local/share/omawe/library.db`. При изменениях разбираются только те `project.json`, у которых сменился mtime.
- **Статичный двойник.** Первый кадр каждых обоев сохраняется в `~/.cache/omawe/twins/` и ставится штатным фоном Omarchy.
  Он лежит слоем ниже рендерера, поэтому при смене обоев, паузе, остановке на время игры или падении рендерера чёрного экрана нет.
  Экран блокировки берёт этот же кадр.
- На каждый монитор — свой процесс рендерера. Поэтому пауза, свойства и смена обоев независимы по мониторам; звук идёт только с первого.
- Смена обоев: новый рендерер стартует поверх старого, старый гасится после первого кадра нового.
- Превью для панели кэшируются в `~/.cache/omawe/thumbs/` (WebP, создаются в фоне при первом открытии).
- Пауза — `SIGSTOP`/`SIGCONT`, процесс не перезапускается.

## Замеры (этап 1)

Core Ultra X7 358H, Arc B390, два монитора 1920×1080@180, питание от сети, scene-обои.

| Что | Результат | Цель из ТЗ |
|---|---|---|
| Демон в простое, 20 с | 0 тиков CPU, RSS 7.9 МБ, 1 поток | < 0.3% CPU, < 15 МБ |
| Вызов `omawe status` | 1.6–1.9 мс | < 20 мс |
| GPU на паузе (`SIGSTOP`) | 0.00% render-движка | ~0% |
| Пауза по монитору за полноэкранной игрой | проверено: закрытый монитор на паузе, второй играет | — |
| GPU в работе, 60 FPS, 2 монитора | 24.5% render-движка | — |
| Первый кадр после `apply` | 880 мс | — |
| Смена обоев целиком | ~1.1 с, без чёрного кадра | < 500 мс — **не достигнуто** |

GPU считан из `/proc/<pid>/fdinfo` (драйвер `xe`), без `intel_gpu_top`.
500 мс недостижимы: сам рендерер отдаёт первый кадр через 0.7–0.9 с, а управления «на лету» у него нет.
Не измерено: расход батареи, аппаратное декодирование видео, холодный старт сессии.

## Ограничения

- **Паузы при блокировке экрана и выключении мониторов нет.** Блокировку делает оболочка Omarchy, и ни она, ни Hyprland
  не сообщают об этом событием; опрашивать состояние по таймеру omawe не будет. Сколько рендерер тратит под экраном блокировки, не измерено.
- **Обои типа application не работают** — `linux-wallpaperengine` их не поддерживает. Они помечены в списке как `unsupported`, применить их нельзя.
- У рендерера нет IPC. Любое изменение (обои, FPS, громкость, масштабирование) — это перезапуск с бесшовной подменой, ~1 с.
- Штатный фон Omarchy и тема одни на все мониторы, поэтому берутся по обоям первого монитора.
- Некоторые обои не отдают кадр-двойник или падают в рендерере; упавшие помечаются `crash` и пропускаются при `next`.
- После обновления плагина оболочка Omarchy перезапускается: она держит в памяти прежнюю версию виджета.
- `playlist.match_theme` и `list --match-theme` используют цвет превью; он вычисляется при первом открытии панели.
- Новая библиотека Steam, добавленная после старта демона, подхватывается после `systemctl --user restart omawed`.
